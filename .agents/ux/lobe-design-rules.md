# 项目文案补充规则

## UX-001・按实际行为翻译排除类文案

- 层级：rule。判断需要结合控件行为；不能仅凭 “不包含” 等字面量全局替换。
- 适用场景：文件列表的显示筛选、忽略规则和统计口径。
- 判据：菜单、按钮和筛选开关应描述点击后的动作。`exclude` 在文件可见性场景用 “隐藏”，筛选场景用 “排除”，统计口径用 “不计入”；不要把动作译成 “不包含” 这样的范围说明。
- 忽略对象存在歧义时，注明规则来源，例如 “Git 忽略文件”，不要让用户猜测是谁忽略了文件。
- 正例：文件显示开关 “隐藏 Git 忽略文件”；浏览统计 “自己的预览不计入浏览次数”。
- 反例：文件显示开关 “不包含已忽略文件”。统计说明中的 “不包含你自己的预览” 属于可选润色，不作为明确错误。
- 边界：套餐权益、模板内容等客观范围说明中的 “不包含” 可以保留；不要机械替换为 “排除”。

## UX-002・文案审查区分错误与偏好

- 层级：rule。需要对照英文、业务场景和控件行为判断，不按关键词机械判错。
- 适用场景：中文文案审查与批量翻译优化。
- 判据：优先报告词义误译、英文句式硬译和影响理解的表达，并说明具体误解；仅有更短、更顺的替代表达时，归为可选润色，不列为明确问题。
- 明确误译示例：固定绑定设备的 fixed 被译为 “修复的”；产品首次使用引导的 onboarding 被译为 “入职”。两者都把业务含义换成了另一种含义。
- 边界：保留自然且准确的现有文案，不为了增加发现数量而改写。
